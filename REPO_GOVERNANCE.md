# Repo Governance

This is the single contributor entry point for repo workflow rules and validation gates; other contributor-facing docs should point here instead of restating them.
Keep changes biased toward deletion, behavior preservation, and one canonical source of truth per workflow.

## Canonical Gates

- Use `mise run dev` for the normal local developer gate.
- Use `mise run affected` when you want changed-file validation with the repo's deterministic fallback.
- Use `mise run verify` before claiming completion; it is the release-readiness gate and already includes reachability audit, main/test/extension typecheck, required native build/parity, protocol drift, tests, coverage, the exact complexity ratchet, lint, build, deterministic observation benchmarks, and isolated tarball install smoke.
- Use `mise run package-smoke` when changing package contents, exports, extension/native assets, CLI installation, or release packaging. It packs exactly one tarball, enforces the allowlist and hard compressed/unpacked/file ceilings, installs from the `.tgz` in a clean temporary project, and verifies the JavaScript fallback without importing the checkout.
- Use `mise run smoke-browser` after changing bridge/daemon/extension/live-browser behavior. It launches an installed Chrome/Edge/Chromium with the unpacked MV3 extension and verifies handshake, tabs, `browser-operation/v2` completion-event settlement and failure classification, full/delta/re-anchor observe, provider budgets, network/hook behavior, BFCache lineage, verified frontier reads, Prerender2 target replacement, target close/new target, and extension reconnect; Windows CI runs the same acceptance gate without skips.
- Use `mise run dev-governance` when changing governance or workflow artifacts.
- Do not teach raw package-script gate commands in governance docs; `mise` is the canonical entrypoint.

## Child-Agent Workflow

- `scout`: gather codebase context, hotspots, and file-level evidence before edits.
- `planner`: turn that evidence into the smallest change set with explicit boundaries.
- `worker`: implement one bounded slice at a time after RED exists.
- `reviewer`: check for regressions, missing tests, and weak evidence before claiming done.
- `oracle`: use only for decision deadlocks or consistency checks that need a second pass.
- Keep the main thread for decisions and proof; delegate independent recon, review, and narrow implementation slices.

## Repository Boundaries

- Treat these as product entrypoints: `index.ts`, `src/apps/cli/bin.ts`, `src/apps/cli/main.ts`, `src/apps/daemon/server.ts`, the extension entry files under `src/bridge/extension/`, and `src/commands/webSecurity/browserNative/callbackOastWorker.mjs`.
- Treat `bridge/browser_pilot_bridge/` as packaged shell output and `dist/` as local build output. Edit source under `src/` and `capture-src/`, then rebuild through the canonical gates.
- Keep public surface changes explicit. Root `index.ts`, the CLI contract, and schema-derived native protocol files are not cleanup fodder.
- Current high-risk zones: `src/bridge/server/`, `src/apps/daemon/`, and `src/bridge/extension/service_worker/`.
- `tsconfig.json` excludes `src/bridge/extension/**`; that code is validated separately by `tsconfig.bridge-src.json` and ESLint's second project binding.

## Public Command Contract

- `src/commands/commandCatalog.ts` is the only public `browser_*` tool list. The public surface has no wait/sleep tool; selector, navigation, and network-idle observers are internal operation-supervisor primitives.
- Every public browser state-changing command must return `browser-operation/v2` and must have a command-specific completion resolver. Governance tests enumerate native protocol write commands and fail when a resolver is missing; acknowledgement or page quiet cannot produce `completed`.
- **Agent Interaction Plane exception (preview):** the agent-preview façade write tool `browser_act` may return `browser-agent-turn/v1` at the public root after it has obtained a full internal `browser-operation/v2` outcome. `AgentOutcome` must be a pure 1:1 mapping of `classifyBrowserOperationStatus()` (`completed` alone is success; non-completed never promotes). Raw operation truth remains available to expert/debug paths; artifact/trace persistence failures must not rewrite the settled status. No other command may invent a custom terminal root.
- Agent-preview tools (`browser_view`, `browser_act`, `browser_read`) are invokable and schema-validatable but are **not** part of the public catalog v3 wire or contract `toolCount` (still 19). Profile filtering lives in `src/commands/capabilityProfileCatalog.ts` (name sets only). Human CLI remains expert-first; agent profile is opt-in via `--profile agent-preview` / structured invoke. Do not silently rewrite catalog v3 or claim agent-default GA without the §22.6-style cognitive gates.
- Agent façade must not auto-replay acknowledged mutations; recovery is deny-by-default for mutation replay after ACK/unknown delivery. Mechanical context is owner-isolated, revision-bound, and identity-aligned with existing `PageIdentity` / `pageReanchorReason` (no parallel identity equality).
- Sensitive façade mutations (submit/navigate/irreversible candidates) require one-shot `confirmationRef` from `ActionConfirmationService` (owner/context/revision/PageIdentity/action digest; secrets never enter digests). Mismatch/expired/consumed must reject without dispatch. Façade turns expose fail-open `traceRef` via `AgentTraceStore` without rewriting settled outcomes.
- Every `withBrowserOperation()` call site must return through `browserOperationCommandResult()` for primitive writes. The root `browser-operation/v2` terminal contract stays inline for primitives; oversized completion/effect/diagnostic evidence is saved once, replaced by a bounded typed summary, and exposed through verified `saved.path` plus `artifact_hints` JSON paths.
- `completed` is the only successful operation status: it maps to `classification:"success"`, `completionVerified:true`, `ok:true`, and CLI exit 0. Every other terminal status is inconclusive or failure, has a stable operation code, keeps `completionVerified:false` / `ok:false`, and maps to CLI exit 1. JSON and TTY rendering must use the shared pure classifier rather than generic error-shape heuristics.
- Artifact persistence is downstream of the browser terminal state and must fail open: a save error reports `ARTIFACT_SAVE_FAILED` and `replay:"do_not_retry"`, but it must never erase or rewrite the already-proven operation status or `completion.source`. A saved operation artifact must fit the artifact reader's byte ceiling before its path is published; the reader ceiling must remain above the default bridge payload ceiling.
- Read-only commands remain immediate. Write commands must arm `operation.begin` before dispatch, preserve target generation, and terminate as `completed`, `effect_observed`, `no_effect`, `stalled`, `ambiguous`, `target_lost`, `failed`, or `deadline`.
- Operation settlement is revision-driven. Begin/update/event/finish/abort/reconnect/replacement advance the operation revision; production waits use `waitForOperationChange()` or the next pure liveness deadline and must not poll the registry, install a fixed interval, or retain a 25ms fallback. Extension events are bound to the exact WebSocket that armed the operation so reconnect-era parallel offscreen sockets cannot lose completion evidence.
- Operation `continuation` is a compact safety decision, not a success claim. Page-state uncertainty uses `observe`; lost, closed, replaced, or fanned-out targets use `reacquire_target`; `inspect_diagnostics` is emitted only when diagnostics exist; non-page uncertainty without diagnostics uses a read-only `verify_command_state`; a compacted successful result uses `inspect_artifact`. None of these decisions may encourage blind replay of an acknowledged mutation.
- Result `nextActions` may expand only final artifact paths that were verified against the persisted layout. Final `saved.bytes` / `saved.chars` descriptors must match the bytes and characters actually persisted, and optional artifact expansion remains in `artifact_hints` rather than being synthesized from correlation IDs.
- The final rendered distilled envelope must honor its committed character budget. Under extreme pressure, retain canonical observation markers, actionable error state, the compact saved descriptor, and at most the required continuation before dropping duplicate diagnostics, artifact metadata, or structural planes.
- CLI artifact read metadata must use bounded placeholder templates and structured field references. Never interpolate an untrusted saved path, JSON path, or snapshot ID into a display shell command; retain the actual saved path once in its artifact descriptor.
- Public schema/help/Skill guidance must not reintroduce a post-action wait, sleep loop, compatibility alias, or optional transaction/monitor switch.
- Public action routing, action help, action schema, and offline validation must use the canonical action catalog derived from registered commands plus generated native metadata. CLI action tokens are kebab-case; raw JSON action values retain their schema-defined spelling. Command-owned synthetic actions must declare one owner and stable schema reference in the command definition.
- Public discovery is contract v3 only. `commands --json` is the compact `browser-pilot-command-catalog/v3` root with one artifact rule, 19 canonical tools, and action schema references; `schema <command> <action> --json` is `browser-pilot-command-schema/v3`. Do not restore per-command flag/schema/artifact duplication, v2 output, legacy action aliases, or a verbose compatibility switch. Catalog UTF-8 size must remain at or below 25 KiB.
- Every public action-specific schema is closed and owns the raw action `const`, shared command fields, allowed nested `params`, required/required-any constraints, and `additionalProperties:false`. Generated native network/hook/frame metadata and command-owned synthetic actions feed the same help, schema, offline validation, daemon validation, execution routing, and command-contract hash.
- CLI offline validation and daemon invocation must use the same strict pipeline: resolve CLI value references, reject unknown/internal/removed keys before normalization, apply only explicit command-owned coercions, validate the strict schema, then run pure semantic validation. Validation failures return the full stable `code` / `path` / `message` issue list and never start the bridge, access a browser, or write artifacts.
- Managed daemon reuse requires exact package, daemon protocol, command-contract version/hash, and tool-count identity in both live status and lock metadata. A mismatch must drain and replace the old daemon before invocation; replacement failure is explicit and must never fall through to the stale daemon.
- Observation baseline, session-delta, perception-ledger, and render-cache identity is `browserSessionId + tabId + targetGeneration + pageEpoch`. URL and optional document id are facts, not equality keys. An unproven or mismatched identity discards the old baseline and returns a full observation with a compact `reanchorReason`.
- Page-world capture crosses the bridge only as the strictly validated camelCase `browser-page-scan/v1` bundle. The extension handshake must report `captureContractVersion:1`; incompatible extensions fail before observe with `EXTENSION_CONTRACT_MISMATCH`, and malformed bundles fail with `SCAN_BUNDLE_INVALID`. Do not add untyped record casts or legacy snake_case readers.
- Canonical observe output is the single `browser-page-observation/v3` root for inline, artifact, cache, full, delta, and re-anchor paths. Do not restore a generic summary root, nested observation wrapper, duplicated content/templates/correlation planes, or an artifact observation mirror. `actionables` stay a compact ref index; detailed entity/collection/template/content/diagnostic expansion belongs to the verified frontier and saved artifact.
- Every folded/truncated frontier item must have a JSON path verified after persistence or an explicit `unavailableReason`. Provider planning reserves core scan/structure and render/persist time before optional causal/axe/Readability I/O; optional work follows the deterministic 2:1:1 split, reports bounded execution telemetry, and fails open without altering canonical structure.
- Observation and distillation cost has one pure owner and one shape: `{chars,bytes,estimatedTokens}`. Final `limits.cost` must equal the actual stable JSON serialization; allocation sorts by estimated tokens with UTF-8 bytes as the tie-break while public `maxChars` remains a hard ceiling.

## Release Workflow

- Only a `v*` tag may start `.github/workflows/release.yml`, and the first gate requires the tag to equal `v${package.json.version}` exactly.
- Ubuntu and Windows must run `mise run verify` plus tarball install smoke; Windows must also run the full `mise run smoke-browser` gate. Any failure blocks packaging and publishing.
- The Ubuntu package job retains one tarball and its SHA-256 manifest from `package-smoke`. The publish job downloads and re-verifies that exact artifact and must never run `npm pack` or rebuild it.
- npm publishing uses a pinned npm 11 CLI, OIDC trusted publishing, `--access public --provenance`, and only `contents:read` / `id-token:write` permissions. Do not add `NPM_TOKEN`, `NODE_AUTH_TOKEN`, or another long-lived publish credential.

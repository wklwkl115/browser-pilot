# Next-Phase Web Reversing And Security Primitives Plan

> Summary archive for
> `docs/archive/next-phase-web-reversing-and-security-primitives-plan.full.md`.

This 2026-05-29 planning-only document froze the original next-phase Web
reversing and security problem areas. Several phase-1 workstreams later shipped
as dedicated archived execution contracts, while the remaining directions stay
as roadmap/RFC context rather than active work.

## Archived Decisions

- New Web reversing/security capability areas must start from internal
  primitives, bridge/native commands, artifact evidence, evals, and contracts.
- Public tool promotion requires non-overlap proof against the canonical tool
  surface.
- One-click workflow tools that decide strategy for the agent remain out of
  scope.
- The historical P0/P1 problem areas were JavaScript AST/deobfuscation,
  request/response intervention, DOM event/sink evidence, WebAssembly reversing,
  and stateful WebSocket replay/fuzzing.

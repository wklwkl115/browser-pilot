# 声明式任务视图：第一版设计草案

状态：第一版已按本文边界实现，实际接口和限制见[任务视图使用说明](task-views.md)。本文保留设计依据及验收要求，不代表所有宿主或真实网站均已验收。适用范围为单 Agent 工作流；保留现有 daemon，不引入客户端身份、任务租约、多 Agent 协作或展示历史缓存。

## 目标与边界

Agent 声明本轮关注对象和信息需求，Browser Pilot 从本次已捕获模型中组织证据。投影不改变页面、不补发浏览器读取、不翻页、不自动选择业务操作对象，也不根据观察兴趣推导写入授权或业务成功。

“规范观察”是本次采集范围内的完整模型，不代表虚拟列表、分页、跨框架或未加载业务数据已经全部采集。任务投影必须保留这些限制。

第一版交付明确引用或文字线索定位、结构上下文补齐、稳定排序、按信息组压缩及快照绑定的展开资源。每次显式传入 `view`，每次返回自包含的当前视图。不做纯增量补丁、隐式持续关注、自然语言规划或语义模型检索。

## 本次审查作出的收敛

1. 删除原建议中的 `consumerViewContext`、客户端隔离和已展示对象缓存。第一版使用当前完整信息组，关注点切换不依赖展示历史。
2. 第一版要求任务规格有明确 `focus`，禁止空对象触发隐式“最近任务”。
3. 区分运行时引用解析与纯模型投影。引用过期、目标归属和页面身份在适配层校验；纯函数只处理已经解析的锚点和规范事实。
4. 明确候选计数单位。候选指去重后的业务对象或结构对象，不能把一个记录的编号、标签和按钮分别计为三条记录。
5. `check` 第一版仅组织目标状态、可关联的页面变化和可见反馈。P0 回执仍通过 `browser_operation` 查询，不根据“最后一次操作”猜测绑定关系。
6. 单独定义任务展开资源。不能将过滤后的数组下标用于读取原规范观察，也不能只回退到整页巨大资源而丢失信息组结构。
7. 预算不足时整组折叠；明确锚点、候选歧义和观察限制仍需有精简的内联说明。

## 拟议公开接口

```ts
type TaskViewSpec = {
  focus: { refs: string[] } | { query: string };
  intent?: "locate" | "read" | "interact" | "check";
  fields?: string[];
};

type ObserveView = "page" | TaskViewSpec;
```

`view` 不提供或为 `"page"` 时保持当前行为，包括现有 `mode` 语义。任务规格中省略 `intent` 时统一默认为 `read`。`fields` 是优先匹配的页面标签或字段名，不能排除对象身份、错误或必要说明。

建议的第一版输入上限为 8 个去重 ref、256 个字符的 query、16 个 fields、每个 field 64 个字符；这些是待实现的防滥用边界，不是当前能力。拒绝空白 query、空 refs、refs/query 同时出现、未知字段和越界输入。去除首尾空白后再校验并保存规范化规格。

模型不接收预算、关系深度、内部 snapshot ID 等机械参数。第一版沿用固定宿主预算策略；后续需要可配置预算时由宿主入口提供，而不是给每次工具调用增加控制项。

## 锚点解析与候选检索

### 明确引用

适配层复用现有 ref 有效期、浏览器归属和页面身份约束。所有 focus refs 必须属于同一观察目标；无显式目标时可依据一致的 ref 归属确定目标，有显式目标时必须一致。跨目标引用或目标冲突应在捕获前拒绝。

捕获完成后再次确认锚点对应的页面身份和当前模型成员关系。失效 ref 不按名称重新匹配；仍有效但未出现在本次采集中的对象报告 `unresolved`，不能直接断言已删除。多个明确锚点任一个无法解析时，不将剩余对象当作完整关注结果。

### 文本线索

第一版采用可解释的字面匹配：规范化空白和大小写，精确匹配优先于子串匹配；不做日期推断、同义词改写或业务规则推理。页面文本始终作为数据，不作为指令执行。

检索规范模型中的名称、已公开的非密码值、字段标签及捕获正文。匹配结果记录字段、匹配方式和原始文本依据。字段名匹配可以提升排序，不能把字段值转换成新业务结论。

同一已知结构对象内的命中合并为一个候选，同时保留命中位置。按“精确匹配、子串匹配、页面顺序、稳定 ref”排序。结构归属不确定时保留分离命中和歧义，不按名称合并不同记录。

正文中有命中但没有可证明的可操作对象关系时，返回正文证据和 `unresolved`，不生成可点击候选。候选总数须明确计数单位，且只针对已捕获范围。

`no-match-in-observed` 只表示按公布的字面规则扫描了相应已捕获输入而无匹配；同时保留采集缺口。模型输入缺失、内部选择计算超限或定位语义不足时返回 `unresolved`。两者均不表示网站全局不存在该对象。

## 信息组与上下文补齐

纯选择函数接收规范观察、规范化任务规格、已解析锚点和固定策略，返回投影计划。它不访问文件、注册表、浏览器或网络。

每个信息组包含身份锚点、原始事实、可选动作、必要上下文、来源引用、缺口及保留原因。来源关系与事实结论分开，时间接近不提升为确定因果。

| 信息组 | 应补齐的信息                                 | 扩展边界                                 |
| ------ | -------------------------------------------- | ---------------------------------------- |
| 字段   | 标签、当前值、状态、关联说明和错误、对象身份 | 不因找到一个输入框而扩展到整页所有控件。 |
| 记录   | 记录标识、相关表头和值、该记录的操作         | 不把相同容器名称当作记录身份。           |
| 弹窗   | 标题、正文、选项、退出路径、已知阻挡关系     | 不把弹窗当作新的业务目标或自动关闭。     |
| 反馈   | 当前对象状态、相关变化、可见的正反信号       | 不把 UI 文本提升为服务端持久化结果。     |

按关系类型定义方向：从控件沿 `labelledBy`、`describedBy` 补到说明；从单元格经结构关系补到行与表头；按 `coveredBy` 补到遮挡对象。仅在存在可验证结构或关系时补齐表单外的 portal 错误。

模型存在 `relations` 并不代表包含了所有 DOM 父子关系。关系断裂、结构不明或内部遍历上限触发时，保留已有事实，标记 `contextIncomplete`；不得宣布“依赖已全部补齐”。

## 必须保留的范围与异常

相关性筛选之前收集：页面身份变化、采集降级、已观察到的阻挡弹窗和告警、目标相关错误、相关集合的分页及虚拟化限制。另保留精简的页面标题和全局导航入口，便于重新定位。

只按观察到的角色、状态和关系描述异常。例如可以报告“存在标题为登录已过期的对话框”，但普通正文中相同词语不自动成为会话失效结论。

强制信息不受普通相关性淘汰，但仍受物理预算限制。无法完整内联时，必须保留异常数量、缺口标记和对应展开入口；不能静默消失。

## 投影结果与预算

沿用现有公开视图，增加有明确 schema 的任务元数据及信息组。拟议元数据包括：

- `status`：`resolved`、`ambiguous`、`no-match-in-observed` 或 `unresolved`。
- `observationScope`：采集范围、集合观测数量、已知分页和采集缺口。
- `matchScope`：匹配方式、检索过的输入类别、候选计数及单位。
- `outputScope`：信息组内联和折叠数量、必要上下文是否完整。

这些状态彼此独立。例如可以已准确定位对象，但其必要上下文因预算而没有完整内联。不要用一个 `complete` 布尔值代替三种范围。

按“强制信息、明确锚点、候选身份、必要上下文、相关变化、补充内容”打包，组内不得只留下脱离记录身份的按钮。折叠组的动作也不应继续以孤立 actionSpace 项出现。

第一版保留现有最终视图 32 KiB 上限，并在生成后检查实际 UTF-8 序列化大小。候选数和折叠数不能通过截断 JSON 实现；采用完整组选择及有界的降级视图。

当前中间件的大小检查只针对视图 JSON；MCP 还会生成文字摘要、结构化内容和资源链接。预算与评测必须分别记录视图字节及最终传输包字节，不把 32 KiB 视图上限当作总响应上限。若将来提供硬性总响应预算，必须在宿主渲染后执行检查。

MCP 文字摘要也必须包含定位状态、候选歧义及缺口；不能只在 structuredContent 中保留它们。只读取文字摘要的宿主也应得到保守的边界信息。

## 展开资源与规范观察

先保存原规范观察，再执行纯选择和打包。不同任务规格不能删除、重排或覆写该规范观察的事实。

建议独立保存版本化的任务投影产物，包含规范观察身份、规范化规格、策略版本、完整的公开信息组和来源索引。保存的是公开证据结构，不直接暴露内部 entity 的定位器等字段。

资源描述符通过受限的组索引读取该产物，绑定项目根、原快照、有效期和任务产物类型。解析器校验真实路径、schema、快照对应关系和索引范围。需要同步扩展现有描述符白名单和 MCP 资源注册逻辑，不能通过放开任意 jsonPath 绕过。

历史资源只读取对应历史产物，不访问当前页面或当前 OperationRegistry。产物或描述符过期时明确不可用。规范观察与投影产物的保留期需协调；不扩展既有清理授权，不删除用户原始证据。

未加载的数据仍使用原 frontier 的分页控件、虚拟化状态或不可用原因。任务资源只包含已捕获的信息组，读取资源不会加载网站下一页。

## 当前视图、变化与 check

任务视图每次返回当前必要信息，即使 `mode: "diff"` 且页面没有变化。不能沿用通用投影中“有 diff 就省略正文”的路径。页面差异只作为附加摘要，不作为当前信息组的唯一来源。

切换 focus、fields 或 intent 会重新选择当前信息组，不创建持续任务状态。无历史基线时，仍返回当前视图并说明变化摘要不可用。

`check` 第一版展示当前证据，不自动注入 P0 操作回执。需要执行、断言或业务结果时调用已有 `browser_operation`。未来若整合，必须显式绑定 operationId，并验证项目、目标、时间和证据来源；不能自动采用最近一次操作，也不能在读取旧任务资源时混入最新回执。

## 实施拆分与验收

| 阶段         | 工作                                         | 必须验证                                                   |
| ------------ | -------------------------------------------- | ---------------------------------------------------------- |
| 契约与纯选择 | 规格校验、候选去重、关系补齐、范围元数据     | 无隐式目标、确定性、不修改输入、无浏览器副作用。           |
| 输出与资源   | 信息组打包、任务产物、受限资源读取、MCP 摘要 | 小预算不产生孤立操作；折叠数据仍可定位；资源绑定历史快照。 |
| 观察链路     | refs 目标解析、页面身份复核、任务分支、文档  | 默认 page 行为不变；任务 diff 自包含；失效锚点不换对象。   |
| 浏览器验收   | 单 Agent 表单与列表流程、低资源支持宿主      | 对象身份、错误、范围和资源引用在完整流程中可用。           |

必要用例包括：

1. 命中位于通用内容或集合裁剪范围之外，仍可从规范观察选中。
2. 同一记录多处命中只算一个有证据归属的候选；不同记录同名按钮保留不同身份。
3. 有关系证据的 portal 错误进入信息组；无证据时报告缺口而不猜归属。
4. 虚拟列表零匹配只描述已观察范围；正文命中不伪造可操作对象。
5. 页面不变、fields 改变，新字段及其必要上下文完整出现。
6. 明确 ref 过期、跨目标、导航后变化、当前采集遗漏分别有正确结果。
7. 连续切换 view 或省略 view 不继承旧关注点。
8. 极小预算、长错误、多候选均保留歧义和降级标记，不留下孤立动作。
9. 更换投影规格不改变规范模型；资源展开后仍属于原快照。
10. 历史资源过期、索引非法、路径越界、schema 不符均明确拒绝。
11. 仅文字摘要的宿主也能看到限制；资源展开所得 ref 可按现有规则使用。
12. check 同时保留正反 UI 证据，但不自行输出业务成功。

评测对比全页模式和任务模式，使用同一模型、相同任务与固定初始状态。统计相关动作召回、必要信息遗漏、孤立动作、错误无匹配结论、错误副作用、任务成功率，以及包括资源读取和重复调用的总响应量；模型 token 仅在实际 tokenizer 可用时计量。

性能收益尚未测量，不预设节省比例。确定性用例中的身份错误、错误全局无匹配及投影副作用必须为零；任务成功率的比较需预先约定样本和判定标准，小样本通过不能证明真实网站不退化。

实现涉及公开契约和浏览器目标解析，应运行全量 verify、构建、真实浏览器 smoke 与新增任务评估。新功能验证须以本次实现对应的结果为准，不以既有测试通过冒充新功能验收。
